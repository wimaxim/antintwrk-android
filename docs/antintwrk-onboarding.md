# Оформление входа antintwrk — 6 октября 2026

Владелец запросил тёмный стиль соцсети, фирменный логотип и удаление отдельного `Messenger sign-in`. На старте остаются «Создать аккаунт» и «Войти». Формы регистрации, входа и восстановления — интерфейсный предпросмотр без серверных запросов.

Источник оформления: опубликованная лента и форма входа antintwrk.com, публичные стили `antintwrk.css`, `antintwrk-auth.css`, `antintwrk-surfaces.css`. Фон `#101214`, поверхность `#1B1E22`, поля `#2B3036`, текст `#F1F1ED`, вторичный текст `#9BA1AA`, акцент `#F06B55`. Фирменный прозрачный PNG `antintwrk-loading-mark-v1.png` скопирован без изменения в `appnav/src/main/res/drawable-nodpi/antintwrk_brand_mark.png`. Шрифтовые размеры используют существующие нативные Compound-токены.

`AntintwrkBrandTheme` применяется только к новым экранам. Оригинальные токены Compound и компоненты чатов/звонков не изменяются. Владелец окна передаётся отдельным CompositionLocal из MainActivity только при включённой новой ветке; оформление системных значков восстанавливается при уходе из неё. Диалог даты получает отдельную тёмную тему и контекст владельца окна.

Включение: `-PantintwrkOnboarding=true`. По умолчанию параметр выключен. Существующие Matrix-сессии, внешний вход и восстановление сохранённого маршрута `MatrixLogin` остаются на прежнем пути. Исходный экран Element доступен в сборке с выключенным параметром. Удаление кнопки не является реализацией единой серверной авторизации: её контракт ещё не подключён.

Системная Android launch-иконка, package ID и тестовая подпись пока исходные. Артефакты проверки хранятся локально в родительской папке `antintwrk-mobile/artifacts/android/branding` и в Git не входят.

## Проверки

Сборка `fdroidDebug` arm64 с `-PantintwrkOnboarding=true` завершилась успешно; APK установлен на эмулятор API 36. Приветствие проверено на русском и английском при светлой системной теме: фон остаётся тёмным, логотип и системные значки видны. Отдельно собран и установлен вариант с выключенным параметром: исходное приветствие Element отображается штатно. Буфер crash log после запуска пуст.

Прошли `:appnav:ktlintCheck`, `:app:ktlintCheck` и семь unit-тестов при обоих значениях параметра: три проверки формы, два штатных теста внешнего входа и два теста владения системными панелями. При переходе загрузка/приветствие могут одновременно находиться в Composition; `AntintwrkSystemBarOwner` восстанавливает родительский стиль только после ухода последнего экрана. Проверены перекрытие и повторное освобождение.

Интерактивные формы, клавиатура и диалог даты на устройстве ещё не проверены. Реальные сессии, переписка и звонки этим этапом не проверялись; серверная авторизация остаётся следующим отдельным этапом.
